# Processware 프로젝트 작업 공간 대화형 UI·UX 상세명세

버전 1.0 · 2026-10-07 · 신규 프로젝트 작업 공간 PW 기준선 · 검토용 설계

## 1. 인터페이스 원칙과 구조

프로젝트 홈 → 생성/선택 → 대화 작업실을 기본 진입 경로로 둔다. 상단은 프로젝트·적용 템플릿·Harness 판·권한·run 상태, 좌측은 업무/자산 탐색, 중앙은 목표 대화, 우측은 산출물·변경·근거 작업 패널이다. 작은 화면에서는 패널을 전환하되 선택 맥락과 작성 중 내용은 유지한다.

필수 업무 결정을 대화 안에서만 숨기지 않는다. 승인·실패·보완은 프로젝트 작업 목록에 남는다. 콘텐츠 편집·관계 확인·차이 비교는 작업 패널에서 제공한다. 표와 양식은 데이터 검토를 위한 보조 수단이다.

## 2. 대화와 맥락 계약

사용자 입력에는 현재 공간, 선택 항목/블록과 판, 요청 유형이 연결된다. Agent는 계획과 조회 출처를 보여주고 필요한 누락만 질문한다. 한국어 IME 조합 중 Enter를 전송하지 않는다. 보내기/중단/새 작업을 명시하고 작업 중 추가 입력은 현재 run 변경인지 별도 작업인지 표시한다.

예시 요청: “이 자료에서 요구사항 초안을 만들고 모호한 항목을 알려줘.” → 원본·권한 확인 → 추출 후보와 미확인 질문 → 선택 항목 편집 → 변경 검토 → 등록. Agent의 답변과 실제 등록 완료를 다른 상태로 표시한다.

## 4. 정밀 편집과 충돌

선택한 필드나 블록의 ID·범위·판을 표시한다. “이 부분만 보완”은 그 범위를 대상으로 제안하며 다른 항목의 수정은 별도 영향 제안으로 제시한다. 수동 편집과 AI 수정은 동일 판 검사·이력 경로를 사용한다.

저장 전 화면에서 draft가 존재해도 서버 반영 완료로 표시하지 않는다. 낡은 판이면 현재판·제안판의 차이를 보여주고 재구성한다. 병합으로 내용이 바뀌면 검토·승인을 다시 받아야 한다. 승인판은 읽기 상태에서 새 수정안 만들기로 진입한다.

## 5. 탐색·관계·출처

Vault는 유형·상태·담당·기간 검색, 구조 트리, 관계 경로, 적용 규칙, 버전 이력으로 탐색한다. 검색에서 발견한 권한 밖 항목을 링크/제목으로 노출하지 않는다. 추적 관계는 단순 링크 존재와 증적 충분성·검토 유효성을 구분한다.

원본 대조 패널은 위치·해시·추출/변환·보정·미확인·사후 확인을 보여준다. 출처가 없으면 “AI 추정”을 사실로 꾸미지 않는다. 출력용 서식 편집은 콘텐츠 작성 흐름과 분리한다.

## 6. 실행·연결 복구

브라우저 재연결은 cursor 이후 실제 이벤트를 수신하고 서버 run 상태와 대조한다. 대화 발화 재전송이 run 생성 재요청으로 이어지지 않도록 요청 키를 보존한다. 비밀정보는 로컬 draft·분석 로그에 넣지 않는다.

중단 버튼은 더 이상 수행하지 않을 단계와 이미 발생한 변경을 보여준다. 외부 결과 불명은 확인 대기로 표시한다. 승인 만료·판 변경·권한 변경 시 대기 카드의 유효성을 갱신하고 오래된 카드로 적용하지 않는다.

## 8. 화면 평가 기준

P1: 템플릿 선택→초안 생성→대화 작성→특정 필드 수정→변경 검토→자체 승인→규칙 위반 보완→기준선 출력→연결 종료 후 재개를 시범 자료로 평가한다.

P2: 승인자의 실제 신원, 서로 다른 권한의 사용자, 동시 수정·승인, 예외·기한·병렬 검토를 검증한다. P3: 외부 지원 한계·배포 영향·실제 원격 확인·왕복 충돌·부분 실패를 평가한다.

텍스트 크기·키보드·포커스·대비·상태 안내를 점검한다. 차단 오류는 해당 항목으로 이동할 수 있어야 하며 작업 내용을 잃지 않는다. 도구 결과를 기다리는 동안 가짜 완료 메시지나 가짜 진행률을 사용하지 않는다.
