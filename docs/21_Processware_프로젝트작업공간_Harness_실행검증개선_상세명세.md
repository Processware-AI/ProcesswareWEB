# Processware 프로젝트 업무 Harness 실행·검증·개선 상세명세

버전 1.0 · 2026-10-07 · 신규 프로젝트 작업 공간 PW 기준선 · 검토용 설계

## 1. 두 Harness의 책임

표준 구축 Harness는 원천에서 조직 프로세스 자산을 만들고 평가한다. 현장 업무 Harness는 승인된 자산을 적용해 프로젝트 콘텐츠·업무를 수행한다. 두 구성은 별도 ID·릴리스·평가·승인 범위를 가지며 동일 모델을 사용해도 권한을 공유하지 않는다.

본 상세 명세의 대표 기능은 PW-08/09/10/12/13/19/21이며 실행 정책과 자료 접근은 PW-16, 외부 도구는 PW-22~24와 연결한다.

## 2. 현장 Harness 릴리스 계약

| 구성 | 정의 |
|---|---|
| process binding | 템플릿·조정·규칙의 고정 판, schema hash |
| role/agent binding | 역할별 담당 범위, 사람 승인 지점, 위임 권한 |
| tools | 도메인 도구/ALM capability, 정형 입력·출력, 허용 동작 |
| context policy | 읽을 수 있는 프로젝트·자산·원본, 검색/제공 범위 |
| execution policy | 단계·분기·기한·예산·중단·재시도·복구 |
| evaluations | 정상·위반·경계·권한·복구 사례, 판정과 검토 |
| release metadata | 버전·해시·제작/승인 주체·호환성·제한·복원 경계 |

지침만 수정한 후보와 도구/검증 코드 변경 후보는 위험과 평가 범위를 구분한다. 자유 코드·관리자 도구·자료 접근을 지침의 문장으로 추가할 수 없다. 실행 도구 계약과 정책을 변경해야 한다.

## 3. 실행 계약과 상태

Run 생성 시 프로젝트·사용자 위임·Harness/규칙/맥락 판·계획·예산을 고정한다. 계획 변경은 영향 검토와 필요 승인을 받으며 내용이 바뀐 후 기존 승인을 재사용하지 않는다.

각 단계는 준비→의도 기록→규칙/권한/승인→도구 호출→결과 확인→Receipt→후속 이벤트로 진행한다. 실패와 외부 결과 불명은 구분하고 확인 후 재시도한다. 사람 응답 대기는 durable task로 남겨 브라우저 종료 후 재개한다.

상태는 준비·진행·사람 응답 대기·성공·실패·중단·부분 완료·확인 필요를 포함한다. 화면은 실제 run/event sequence를 조회한다. 중단 요청은 아직 실행하지 않은 작업을 막고, 호출 중 작업의 완료 여부를 별도로 확인한다.

## 4. 프롬프트와 규칙 집행의 경계

Agent는 의미 판단·초안·영향 후보·설명을 담당한다. schema·권한·상태·필수 필드·승인·호출 제한은 server 검증기와 domain command가 집행한다. 문서 내부 지시는 신뢰된 실행 권한이 아니며 데이터로 취급한다.

의미 판정도 출처·기준·불확실성·사람 검토 필요 여부를 남긴다. 존재하는 링크가 충분한 증적을 뜻하지 않는다. 규칙 판정 불가나 미지원 통제가 통과로 바뀌지 않도록 한다.

## 5. 변경 후보·평가·릴리스

**현장 오류/수정 기록 → 개선 후보 → 이용권·민감 정보 검사 → 기준 후보 고정 → 격리 평가 → 결과 비교 → 전문 검토·승인 → 불변 릴리스 → 프로젝트별 적용 승인 → 운영 관측**.

평가에는 내용 품질뿐 아니라 금지 도구·무권한 자료·승인 우회·낡은 판·중복 이벤트·외부 타임아웃·예산 초과를 포함한다. 개인정보·고객 비밀·제한 표준 원문이 후보나 공통 평가 사례에 유입되지 않도록 검토한다. 모델 자동 학습은 본 범위가 아니다.

baseline/candidate는 같은 자료와 고정 정책으로 비교한다. 시나리오 버전·모델 설정·도구/규칙 판·시간·비용·실패·전문가 수정량을 기록한다. 안전 통제 실패를 평균 품질 점수로 상쇄하지 않는다. 통과 임계값은 업무 사례별 승인한다.

## 6. 판 갱신과 복귀

프로젝트는 새 Harness가 승인돼도 자동 갱신되지 않는다. 진행 run은 기존 판 유지·중단/재계획을 선택한다. 새 정책과 데이터 schema가 호환되는지 검사하고 이전 결과를 기록한다.

복귀는 이전 실행 구성 선택이며 이미 바뀐 콘텐츠·외부 업무·승인 사실을 자동 지우는 것이 아니다. 대상별 보완·복구 작업을 검토한다. 회귀 문제는 새 평가 사례로 편입한다.

## 7. 수용·운영 게이트

P1: 고정 판·허용 도구·단일 사용자 자체 검토·실행 재개·중복 방지·실제 결과 확인 평가. P2: 실제 역할 분리·동시성·예외·갱신·권한 경계 평가. P3: 실제 ALM 환경의 부작용·권한·부분 실패·readback 평가.

PW-AT08/10/13/14/15/16이 실행·갱신·정책·승인 경쟁·예외·외부 지원의 핵심 평가다. 평가 통과 자료가 없는 릴리스는 미검증 초안으로 유지한다.
