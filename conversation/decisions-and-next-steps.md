# Processware 주요 결정사항 및 다음 과제

2026-10-09 · 전체 대화를 토대로 작성한 인계용 요약. 대화 원문은 transcript.md를 참조한다.

## 1. 제품의 방향

하나의 플랫폼에 전문가의 표준 프로세스 자산 구축 영역과 현장 프로젝트 작업 공간을 둔다. 전문팀은 여러 표준·가이드·기존 조직 파일을 바탕으로 자산과 구축 Harness를 관리한다. 현장은 승인된 템플릿을 프로젝트에 적용하고 업무 Agent와 산출물을 작성·검토·관리한다. 모든 조직원이 표준 구축 과정을 배울 필요는 없다.

표준 프로세스 자산 세트는 정적 활동·역할·입출력뿐 아니라 동적 흐름·필드/관계 정합성·필수사항·제약·제한·예외·근거·판을 포함한다. AI가 도출한 규칙 후보와 표준 의무·조직 운영 결정을 구분한다. 규칙은 프롬프트뿐 아니라 서버와 도구 실행 통제에서도 집행한다.

사용자 접점은 대화와 정밀 편집·검토 화면이다. 파일 서식 편집보다 구조화된 콘텐츠 생산을 중심에 둔다. Office·PDF는 기존 자료 유입과 보고·제출용 출력으로 사용한다. Vault는 항목·관계·출처·판·승인·실행 기록의 관리 계층이며 Git 사용 자체가 제품 요구사항은 아니다.

## 2. 표준 구축과 프로젝트 실행

- 다중 표준을 새로 통합하거나 기존 기준선에 다른 표준을 추가한다. 공통 항목을 재사용하되 원 표준별 의무와 고유 조건을 유지한다.
- 승인된 템플릿 판으로 프로젝트 공간을 생성한다. 기존 실제 기록·승인·비밀정보는 복제하지 않는다.
- 프로젝트 조정과 실제 수행은 독립적으로 관리하고 적용 템플릿·Harness 판을 추적한다.
- 현장 자료를 정비해 증적과 재사용 사례로 축적하되 없는 사실·서명·승인을 만들어내지 않는다.
- Agent 수행 결과와 전문가 수정 사례로 Harness를 평가·개선한다. 프로젝트 수정이 조직 표준·공유 Harness·모델 학습에 자동 반영되지 않는다.
- Redmine·Jira·Codebeamer는 실행·배포·동기화 후보이며 제품/판/권한별 실제 검증이 필요하다.

## 3. 문서 기준선

기존 00~11 문서군: 주요 문서 0.6, 구조도·화면 흐름 0.4. 기능 요구사항 108개, 비기능 25개, 업무 규칙 34개, 화면 16개, 인수 시나리오 56개.

신규 12~23 문서군: 프로젝트 작업 공간 1.0. 기능 24개(P1 15·P2 6·P3 3), 비기능 12개, 업무 규칙 15개, 모듈 8개, 화면 8개, 화면 흐름 12개, 상세 인수 시나리오 16개. 신규 기획서 자체의 인수 시나리오는 12개이며 상세 명세가 4개를 추가한다.

두 문서군은 별도 기준선이다. 기존 S1~S3과 신규 P1~P3을 동일 단계로 해석하지 않는다. 신규 내부 현장 공간은 기존 파일/외부 시스템 사용 경로를 확장한 별도 구현 범위다.

## 4. 구현과 운영에 대한 제안

사용자가 확정한 초기 운영 환경은 개인 서버 설치·원격 접속이다. 처음은 전문 사용자 1명이며 현장 다중 사용자 개방에는 별도 권한·격리·동시성 검증이 필요하다.

무료 Full Stack FastAPI Template 기반 Python API·React UI·PostgreSQL 등은 구현 제안이다. Tiptap OSS는 콘텐츠 편집 후보이며 유료 확장 사용은 확정하지 않았다. 실행 worker·명시적 승인·판 검사·원본/첨부 저장·복구·ALM 어댑터는 추가 설계·구현이 필요하다.

## 5. 아직 확정하거나 만들지 않은 것

- MVP 범위·완료 기준: 표준 구축과 현장 실행을 첫 버전에서 어디까지 연결할지 확정.
- 실제 시범 프로세스·프로젝트 자료와 전문가 정답·누락 사례.
- 최종 데이터 schema, 동적 규칙 표현, 이벤트·도구·승인 API 계약.
- 대화→정밀 편집→변경 검토→승인→실행을 확인할 실제 화면 시제품.
- 모델·자료 처리 위치, 서버·인증·백업·보존·비용 상한, 수치 성능 목표.
- 첫 ALM 대상·버전·권한과 실제 지원표·왕복·복구 검증.
- 표준별 구매/선택 자산 패키지 수입·공급자 업데이트의 세부 신규 요구사항.

첫 시범으로 승인된 템플릿 하나를 이용해 프로젝트 생성→Agent 작성→검증/검토→기준선/출력의 한 사이클을 평가하는 방안은 제안 단계다. 사용자가 특정 시범 프로세스나 범위를 최종 승인한 것으로 해석하지 않는다.

## 6. 완료 상태

문서 구조·요구사항 매핑·의존성·링크 및 원본 보존을 검사했다. 실제 웹 애플리케이션 구현, 화면 시제품, 실제 ALM 연동, 제품 인수 시험은 아직 수행하지 않았다. 이 저장소 업로드는 문서 및 기획 대화 인계다.
