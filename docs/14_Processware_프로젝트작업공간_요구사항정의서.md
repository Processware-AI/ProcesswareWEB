# Processware 프로젝트 작업 공간 요구사항정의서

버전 1.0 · 2026-10-07 · 신규 프로젝트 작업 공간 PW 기준선 · 검토용 설계

## 1. 범위·기준선·용어

[신규 기획서](12_Processware_프로젝트작업공간_신규기획서.md)를 상세화한다. 기존 문서의 번호·범위·S1~S3 단계는 수정하지 않는다. PW 기능 24개를 유지하며 P1 15개·P2 6개·P3 3개다. 전 단계 필수 목표인 Must로 정의하되 해당 단계가 구현될 때 수용해야 한다는 뜻이다. 현재 구현 상태는 모두 정의 단계다.

Workspace는 프로젝트 운영 경계, Vault는 콘텐츠·관계·근거·판의 관리 계층, Overlay는 프로젝트 조정판, HarnessRelease는 평가된 실행 구성, Run은 고정 판으로 수행하는 작업, ChangeProposal은 검토·적용 대상, Receipt는 실제 실행 결과, Baseline은 선택된 불변 항목 집합이다.

P1은 운영자 1명의 내부 시범이다. 프로젝트 범위·권한 검사는 처음부터 포함하고, 다중 사용자·역할 분리와 동시 운영은 P2에서 검증한다. ALM 구성·왕복·확장은 P3의 실제 대상 평가를 전제로 한다. P1 작업은 독립 검토로 표시하지 않는다.

| ImprovementProposal | project_source_refs, generalized_content, rights_review, destination, receipt | 상위 조직 변경은 별도 검토·승인 |

## 6. 상태 모델

| 객체 | 대표 상태 | 전이와 예외 |
|---|---|---|
| Workspace | 초안 → 검증 중 → 활성 → 종료/보관 | 미결 필수 통제는 활성화 금지. 중단은 run 상태와 별개 |
| AssetRevision | 초안 → 검토 요청 → 검토 중 → 승인 → 대체/보관 | 반려·보완은 새 검토 흐름. 승인 수정은 새 판 |
| ChangeProposal | 준비 → 검증 → 검토 대기 → 승인/반려 → 적용 중 → 적용/실패/부분 적용 | 판 충돌이면 재구성·재검토. 승인≠도구 성공 |
| Run | 준비 → 진행 → 사람 응답 대기 → 진행 → 성공 | 실패·중단·부분 완료·확인 필요. UI 종료는 취소 아님 |

전이는 템플릿별 상태 정의로 제한한다. 모든 변경 경로에서 기대 판, 역할, 승인·필드·관계 규칙을 동일하게 검사한다. UI·Agent 도구·API가 각각 다른 통제 경로를 만들면 안 된다.

## 7. 서비스·API 계약 제안

다음은 신규 서비스 경계 제안이며 현재 저장소의 구현 API라는 뜻이 아니다. 서버가 프로젝트 범위를 확인하며 클라이언트 project ID만 신뢰하지 않는다.

| 계약 | 입력·출력 | 핵심 통제 |
|---|---|---|
| Workspace create / activate | template release + overlay → workspace / validation | 요청 idempotency key·정의 호환·활성 승인 |
| Asset query / propose / apply | 항목 판·구조화 patch → 제안·새 판 | scope·expected_revision·patch_hash·approval |
| Validate / transition | 대상 판·전이 → 판정·Receipt | 서버 결정적 규칙·실제 역할·유효 승인 |
| Run start / stream / stop / resume | 고정 설정·cursor → run·실제 이벤트 | durable 상태·도구 키·중단/부작용 구분 |
| Approval decide | 요청 ID·대상 지문·결정 → 유효 결정 | 만료·판·권한·동일인·중복 검사 |
| Baseline / export | 선택 판·출력 정책 → manifest·파일 영수증 | 권한·해시·누락·실제 생성 확인 |
| Migration / deployment / sync | 검토된 계획 → 단계 결과·원격 확인 | 외부 영향·제품별 지원·기준 시스템 |
| Improvement prepare / submit | 원 사례·일반화·권리 검토 → 제안·수신 | 프로젝트와 조직 승인 경계 유지 |

오류 계약은 validation_failed, stale_revision, forbidden, approval_required, expired_approval, unsupported_capability, external_result_unknown, partial_failure, budget_exceeded 등을 포함한다. 오류에는 허용된 범위의 규칙·대상·복구 경로를 표시하고 민감 데이터는 노출하지 않는다.

## 9. 미결 결정과 운영 게이트

시범 자료 형식·평가 정답, 첫 템플릿의 규칙 언어, 모델·데이터 처리 환경, 서버 OS·원격 인증, 백업 RPO/RTO와 보존, 출력 서식, 첫 ALM의 제품 판·접속 권한을 확정한다. 숫자 목표 미확정은 무제한 운영 허용이 아니다. 해당 운영 단계 전에 책임자가 제안 목표와 평가 자료를 승인한다.

PW-22~24는 실제 API·제품 라이선스·권한 지원에 의존한다. 기존 ALM 코드와 문서가 있다는 사실만으로 신규 작업 공간의 배포·왕복·복구 계약을 충족했다고 표시하지 않는다.
