# Processware 프로젝트 작업 공간 배포·ALM 연동·증적·환류 상세명세

버전 1.0 · 2026-10-07 · 신규 프로젝트 작업 공간 PW 기준선 · 검토용 설계

## 1. 배포와 실행의 구분

상위 템플릿 배포는 workspace의 적용 정의를 제공한다. 내부 공간 활성화와 외부 ALM 구성은 실행 설정·권한·지원표를 검증한 별도 행위다. 파일·생성안·mock·실제 활성·외부 전달·원격 반영 확인은 구분한다.

대표 요구사항은 PW-01/02/15/19/20/21/22/23/24다. 상세 제품 지원은 실제 대상에서 확인한다. 기존 배포 명세의 파일 회수는 본 공간의 유입 경로로 재사용하되 내부 workspace 구현 완료로 간주하지 않는다.

## 3. ALM capability와 규칙 매핑

대상 제품명·버전·Cloud/Data Center/설치 방식·접속 주체·필요 권한·rate limit·가능 작업·제한·실제 평가를 기록한다. 프로세스별 필드, 유형, 상태/전이, 관계, 검토/승인, 이벤트, 조회/변경, 파일, 식별자/버전, 복구를 지원표에 포함한다.

각 규칙은 native enforcement, service enforcement, post-detection, unsupported로 분류한다. 외부 사용자가 Processware를 거치지 않고 변경할 수 있으면 service enforcement가 모든 전이를 막는다는 보장을 하지 않는다. 플러그인·권한·대체 통제로 우회 경로를 막거나 사후 탐지의 한계를 승인받는다.

규칙 ID→대상 필드/전이/검증→적용 방법→평가 결과를 매핑한다. 미지원 필수 규칙은 배포 금지 또는 조직 정책에서 허용한 대체 통제 승인 대상이다. 대상에 같은 이름이 있어도 의미·scope·판이 일치하는지 확인한다.

## 4. 실제 배포와 복구

사전 조회·현장 수정 확인 → 구성 차이 → 단계 계획 → 권한/정합성 검사 → 승인 → 변경 intent 기록 → 실제 호출 → 응답/readback → 단계 Receipt → 결과·미완료·제한 보고.

각 단계는 deployment ID·step key·remote ID/revision을 기록한다. 부분 실패 시 실제 성공을 지우지 않고 재시도·보완·수동 확인을 선택한다. rollback 가능한 구성 변경과 되돌릴 수 없는 업무/증적 변경은 구분한다. 운영 프로젝트의 필드 삭제·상태 변경은 데이터 영향을 검토한다.

## 5. 왕복 연동과 기준 시스템

요구사항 본문은 Vault, 실행 상태는 ALM 등 객체/필드별 소유 정책을 정하고 매핑한다. 양쪽 모두 수정 가능한 경우 충돌 해결자·판 비교·승인·보존 정책을 둔다. 제목/파일명만으로 동일 항목을 확정하지 않는다.

출처 변경키·remote revision·last synchronized version으로 반복 동기화를 억제한다. 지연/중복/순서 역전·권한 만료·삭제·외부 첨부 변경을 처리한다. 외부 삭제는 내부 증적의 영구 삭제를 자동 유발하지 않는다.

## 6. 원본 유입과 증적 정비

외부 파일/ALM 결과의 원본·판·수집 시점·제출 주체 확인 수준을 보존한다. 구조화된 항목으로 매핑할 때 관측·변환·미확인·상충·보정·사후 확인을 구분한다. missing 필드를 AI 추정으로 완료 처리하지 않는다.

작성 사실 확인은 담당자의 실제 응답·증빙·시점을 기록한다. 전문가 대리 입력과 원 작성자의 확인을 구분한다. 내부 검토와 외부 심사 판정은 별개다.

## 7. 기준선·출력·백업

기준선은 선택 자산판·관계·규칙/템플릿/Harness 판·승인·증적 참조를 고정한다. manifest는 포함/제외·해시·생성 주체·기간·목적·변환 판을 기록한다.

P1은 웹 열람 및 Markdown/JSON·허용 첨부 묶음과 복원 평가를 제공한다. P2는 실제 보고/제출 사례의 PDF·DOCX·증적 색인을 추가한다. 출력 서식과 내용은 분리하며 출력 파일을 되가져오면 원본 보존·변경 매핑·검토를 거친다. 파일 출력이 콘텐츠의 새 기준 정보가 되지는 않는다.

일반 export는 전체 운영 백업이 아니다. DB·파일·권한·실행 상태의 일관된 백업과 별도 환경 복원으로 hash/관계/승인/run 기록을 점검한다. 비밀정보 복구는 별도 키 관리 정책을 따른다. RPO/RTO·보존·오프서버 사본은 운영 단계 전에 확정한다.

## 8. 조직 지적 자산·Harness 환류

재사용 후보 추출 → 프로젝트 책임자의 이용 범위 검토 → 민감 정보 제거·일반화 → 조직 전문팀의 검토 → 별도 조직 자산/평가 승인 → 수신 영수증·향후 적용 연결.

회사 공통 표준에 적용할 의무와 프로젝트 고유 조건을 구분한다. 사례는 원 사례와 관계를 유지하되 접근 범위가 다른 프로젝트의 실제 자료를 링크로 누출하지 않는다. 승인되지 않은 현장 기록은 공통 Harness 평가·모델 학습에 사용하지 않는다.
