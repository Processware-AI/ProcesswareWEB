## 1. 전체 화면 목록

## PW-UI01 프로젝트 홈

단계: P1 · 요구사항: PW-01

프로젝트 목록 → 선택 → 권한 확인 → 현재 공간·담당 업무 → 작업실 진입.

```mermaid
flowchart TD
  N0["프로젝트 목록"]
  N1["선택"]
  N2["권한 확인"]
  N3["현재 공간·담당 업무"]
  N4["작업실 진입"]
  N0 --> N1
  N1 --> N2
  N2 --> N3
  N3 --> N4
```

예외·복귀: 무권한 공간은 표시하지 않는다. 공간 미선택 상태에서 업무 실행을 시작하지 않는다.

## PW-UI02 생성·조정

단계: P1 · 요구사항: PW-02 PW-03 PW-11

템플릿 선택 → 범위·역할 조정 → 규칙 검토 → 정의 검사 → 오류 보완 또는 생성안 승인 → 공간 활성화.

```mermaid
flowchart TD
  N0["템플릿 선택"]
  N1["범위·역할 조정"]
  N2["규칙 검토"]
  N3["정의 검사"]
  N4["오류 보완 또는 생성안 승인"]
  N5["공간 활성화"]
  N0 --> N1
  N1 --> N2
  N2 --> N3
  N3 --> N4
  N4 --> N5
```

예외·복귀: 검사 실패→해당 조정 항목으로 복귀. 취소→초안 보존/폐기 선택. 필수 미결→운영 활성화 금지.

## PW-UI03 대화 작업실

단계: P1 · 요구사항: PW-06 PW-08 PW-09

의도 입력 → 허용 맥락 조회 → 계획·질문 → 실행 구성 확인 → 실행/승인 대기 → 결과 패널 → 다음 업무.

```mermaid
flowchart TD
  N0["의도 입력"]
  N1["허용 맥락 조회"]
  N2["계획·질문"]
  N3["실행 구성 확인"]
  N4["실행/승인 대기"]
  N5["결과 패널"]
  N6["다음 업무"]
  N0 --> N1
  N1 --> N2
  N2 --> N3
  N3 --> N4
  N4 --> N5
  N5 --> N6
```

예외·복귀: 정보 부족→질문 대기. 사람 승인 필요→PW-UI05. 연결 종료→서버 상태 조회. 중단→완료 단계·부작용 확인.

```mermaid
  N1 --> N2

  N3 --> N4

```

예외·복귀: 추출 실패→원본/미지원 안내. 판 충돌→차이 비교→제안 재구성. 승인판 수정→새 수정안.

## PW-UI05 변경·검토·승인

```mermaid
flowchart TD
  N0["요청 선택"]

  N2["규칙 검사"]
  N3["보완/반려 또는 승인"]
```

## 3. 핵심 업무 흐름

### 3.1 대화 변경과 판 충돌

```mermaid
flowchart TD
  A[선택 자산 판으로 수정 요청] --> B[변경 제안·근거·영향]
  B --> C{현재 판 일치?}
  C -->|아니오| D[차이 검토·제안 재구성]
  D --> B
  C -->|예| E[규칙·권한 검사]
  E --> F[필요 검토·승인]
  F --> G[적용 직전 판·승인 재검사]
  G --> H[새 판·outbox·Receipt]
```

### 3.2 이벤트·외부 실패 복구

```mermaid
flowchart TD
  A[변경 이벤트 수신] --> B{같은 처리 키 존재?}
  B -->|예| C[기존 결과 확인]
  B -->|아니오| D[판·권한·규칙 검사]
  D --> E[후속 작업 실행]
  E --> F{결과 확인 가능?}
  F -->|예| G[단계 Receipt·완료]
  F -->|아니오| H[확인 대기·원격 조회]
  H --> I[미완료 단계 재시도 또는 수동 조치]
```

### 3.3 템플릿 갱신·환류

```mermaid
flowchart TD
  A[새 템플릿/Harness 릴리스] --> B[차이·데이터·권한·진행 run 영향]
  B --> C[이전 계획 검토·승인]
  C --> D[적용·사후 검사·이력]
  D --> E[프로젝트 실행 사례]
  E --> F[일반화·이용권·민감 정보 검토]
  F --> G[상위 개선 제안 수신]
  G --> H[조직의 별도 검토·승인]
```

총 12개 흐름: 전체 1개, 화면별 8개, 핵심 3개. HTML은 외부 렌더링 서비스 없이 동일 정의를 노드·연결 흐름으로 표시한다. 조건·실패·복귀는 해당 흐름과 예외 설명을 함께 읽는다.
